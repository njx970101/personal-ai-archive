# AI-READWRITE: 工作流与协作偏好

## 工作习惯

- 工作时段/节奏：尚未确认
- 做事偏好：倾向让 AI 直接检查现状、执行已明确的修改并完成验证；不要只停留在建议或承诺
- 任务优先级规则：先恢复可用功能和满足明确需求，再做解释或整理；用户纠正目标后应按最新要求调整
- 交付标准：说明具体改了什么、是否重启、测试/运行结果和仍存在的限制；没有实际验证时不要声称已完成

## 常用工具

| 工具 | 用途 | 使用偏好/约束 |
| --- | --- | --- |
| Windows / PowerShell | 日常设备与本地项目操作 | 时区配置为 Asia/Shanghai |

## 沟通风格

- 常用沟通风格：中文、直接、具体
- 回答长度：偏简洁；排查问题时给出证据和必要细节
- 语言与格式：使用简体中文；技术名词可保留英文；优先给出执行结果和可验证状态
- 应避免：只口头说“已完成”但未检查运行状态；擅自新建 API key 或在 DSH 模型列表增加内部回退 provider；将账号登录误说成 API key 已有效；反复询问已明确授权的操作

## 协作规则

- 开始执行前：检查实际配置、日志和运行环境，保护既有改动
- 遇到不确定信息：先独立查证；区分观测事实、推断和未知，避免编造
- 涉及外部写入/发布：只有在用户明确授权目标时执行；公开仓库只写适合公开的信息，不保存密钥或私人资料
- 结束任务时：报告文件/功能变更、测试或运行验证、关键限制；提供仓库链接或提交记录
